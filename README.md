# arcextension — куратор вкладок

Реконструкция механик Arc (Spaces / Air Traffic Control / Auto Archive / Library /
Command Bar) поверх нескольких изолированных инстансов Brave.

Каждый тематический браузер — отдельный `.app` со своим `--user-data-dir`. Сервис
следит за вкладками всех инстансов и постфактум сортирует их по правилам
«адрес → домашний инстанс», не мешая открывать что угодно где угодно.

## Компоненты

- `src/` — **curator-service**: Python-сервис (WSS-канал расширений, HTTP API,
  HTML-консоль оператора `/admin`, MCP over streamable HTTP, SQLite).
  Разворачивается в Docker на инфре.
- `extension/` — MV3-расширение для каждого инстанса Brave: репортит вкладки,
  исполняет команды, даёт попап для правил и newtab-стартпейдж.
- `startpage/` — Vue 3 + Vite, собирается в папку расширения.
- `tools/` — генератор инстансов: собирает одну общую папку расширения на весь парк
  и заворачивает её в `.app` с собственным профилем ([`tools/README.md`](tools/README.md)).
- `deploy/` — рунбук эксплуатации ([`deploy/DEPLOY.md`](deploy/DEPLOY.md)) и правила
  алертов.

## Как это работает

1. Папка расширения одна на весь парк, инстансы отличаются только профилем. Новый
   браузер начинает работать не после копирования папки, а после того, как оператор
   одобрил его заявку в консоли `/admin`: инстанс генерирует себе персональный
   секрет и предъявляет его дальше сам (enrollment).
2. Расширение каждого инстанса держит исходящее WSS-соединение к сервису и
   зеркалит в него состояние вкладок.
3. Правило `pattern → instance` задаёт домашний инстанс для адреса. Правила
   заводятся в один клик из попапа расширения.
4. Раз в `PASS_INTERVAL_MIN` минут проход куратора берёт вкладки, которых не
   касались дольше `IDLE_MINUTES`, и переселяет их: с правилом — домой,
   без правила из тематического инстанса — в `main`. В `main` без правила
   вкладка живёт вечно.
5. Всё, что куратор закрыл или переселил, попадает в архив и восстанавливается
   в один клик.

## Локальная разработка

```bash
make install           # .venv + dev/test-зависимости
cp .env.example .env   # заполнить значения
make test
make run
```

`METRICS_TOKEN` и `ADMIN_TOKEN` обязательны и должны различаться даже локально:
пустое или совпадающее значение валит старт. Остальные цели — `make help`.

## Развёртывание

Прод — Docker: готовый образ из `ghcr.io`, на проде ничего не собирается.
[`docker-compose.yml`](docker-compose.yml) в корне — шаблон, все секреты в нём
плейсхолдеры `XXX`. Переменные в проде задаются в `environment:` compose-файла
(`.env` — только для локального запуска). Ниже порядок шагов и ссылки; конкретные
значения, пороги и процедуры живут в рунбуке [`deploy/DEPLOY.md`](deploy/DEPLOY.md).

**Откуда образ. Рабочий тег — `:develop`.** GitHub Actions
([`.github/workflows/ghcr-check-publish.yml`](.github/workflows/ghcr-check-publish.yml))
на пуш в `develop` собирает и публикует `ghcr.io/vvzvlad/arcextension:develop` — это
тот образ, который стоит на проде. Сборка зависит от джобы тестов (в неё же входит
`make alerts`), так что красные тесты или сломанные правила алертов образа не дают.
Контейнер несёт метку watchtower, поэтому новый образ доезжает **сам**, без ручной
команды: слияние в `develop` — это и есть выкатка. Руками, если ждать некогда —
`docker compose up -d --pull always`.

Роллинг-редеплой поэтому штатный режим, а не событие. Он безопасен by design —
fencing-epoch аренда и перечитывание `user_version` внутри транзакции — и «умная»
оркестрация со свапом назад его ломает:
[§2](deploy/DEPLOY.md#2-rolling-redeploy-is-the-normal-mode).

Ветка `main` зарезервирована под релизы (`:latest` + `:<sha>`), но пока не заведена,
и `:latest` не публиковался ни разу — не пинь его в compose.

### Порядок установки

1. **Сервис не должен быть доступен из интернета** — чем это обеспечено (метки
   traefik, файрвол, VPN), решает инфраструктура:
   [§3](deploy/DEPLOY.md#3-private-network--not-reachable-from-the-public-internet-12).
2. **`ADMIN_TOKEN` и `METRICS_TOKEN`.** Оба обязательны, пустое значение — отказ
   старта, и они обязаны различаться (совпадение — тоже отказ старта). `ADMIN_TOKEN`
   открывает `/admin`, `/api/*` и `/mcp`; `METRICS_TOKEN` — только `/metrics`, и это
   он лежит открытым текстом в `deploy/scrape.yml`. Общего токена для `/ext` больше
   нет: браузеры аутентифицируются персональным секретом.
   [§5](deploy/DEPLOY.md#5-tokens--volumes-recap).
3. **`docker compose up -d`**, дальше — постановка браузеров. Маркер непрерывности
   создавать руками не нужно: entrypoint пишет в него свежий uuid на первом старте,
   если файла нет, и никогда не переписывает существующий. Ручным остаётся ровно один
   шаг — вписать в маркер **новое** значение при восстановлении из бэкапа
   ([§8](deploy/DEPLOY.md#8-restoring-the-db-from-a-backup-7)).

**Один том** `curator` → `/app/data`, и в нём всё изменяемое состояние: БД
(`/app/data/curator.db`), копии (`/app/data/backups`, `BACKUP_DIR`) и маркер
(`/app/data/restore/continuity-marker`, `RESTORE_MARKER_PATH`). Цена решения —
в [§5](deploy/DEPLOY.md#5-tokens--volumes-recap): копии делят место с БД, а откат
тома целиком (снапшот хранилища) вернёт и маркер, то есть окажется необнаружимым.
Штатная процедура восстановления (§8) кладёт обратно **файл** БД, а не том: маркер
её переживает, и детектор работает.

### Постановка браузера

Папка расширения одна на весь парк — инстанс добавляется не копированием, а
enrollment'ом:

1. `make bundle OUT=~/dist` — один раз на парк: общая папка расширения для всех
   инстансов. Больше ничего не требуется — ключей нет, id расширения не пинится и
   нигде не используется: ни `/ext`, ни CORS `/api/*` origin не проверяют.
2. `make instance INSTANCE_ID=… BUNDLE_DIR=~/dist OUT=~/instances [TITLE="…"]` —
   `.app` со своим профилем. Копия расширения не создаётся, лаунчер
   `--load-extension` смотрит в общую папку. Клон `.app` инстанса не добавляет: у
   свежего профиля свой `install_uuid`, он проходит enrollment отдельно.
3. В `/admin` открыть окно enrollment (`ENROLL_WINDOW_MIN`, по умолчанию 10 минут) и
   взять показанный код.
4. В настройках расширения нового инстанса ввести адрес сервиса и этот код — заявка
   попадёт в список ожидания. Свою заявку опознают по префиксу `install_uuid`: он
   печатается и на странице настроек, и в консоли.
5. **Одобрить заявку, пока окно ещё открыто** — approve при закрытом окне отвечает
   409, и тогда нужно открыть новое окно.

Что делать, если окно закрылось или истёк TTL заявки, и как отзывать инстанс —
[§7 «Adding a browser»](deploy/DEPLOY.md#adding-a-browser-the-enrollment-procedure);
про генератор и ручную приёмку — [`tools/README.md`](tools/README.md).
